# 난곡사거리 보행 신호 검증

기준일 2026-11-21 (KST). 대상은 서울 관악구 미성동 난곡사거리 반경 500m다. 요청·필드 명세는 [T-DATA 조사](./seoul-traffic-api.md)를 따른다.

## 실제 데이터 검증 현황

| 항목                             | 결과                                                   |
| -------------------------------- | ------------------------------------------------------ |
| 10121 인증                       | 미검증. 재발급 키가 로컬에 설정되지 않아 호출하지 않음 |
| 10381 인증                       | 미검증. 재발급 키가 로컬에 설정되지 않아 호출하지 않음 |
| 실제 조회한 교차로 목록·ID       | 미검증. 기록할 응답 없음                               |
| 500m 이내 교차로 수              | 미검증                                                 |
| 보행자 신호 제공 여부            | 미검증                                                 |
| 실제 응답에 포함된 상태 종류     | 미검증                                                 |
| 잔여시간 단위와 현시 전환 의미   | 미검증. 공식 문서의 단위 표기가 일치하지 않음          |
| 전송 지연·갱신 간격              | 미검증. 화면의 10초 기준은 로컬 진단용 가정            |
| 횡단보도 실위치와 방향 그룹 대응 | 미검증. 교차로 중심점 및 방향 코드만으로 확정 불가     |

서울연구원 자료에서 난곡사거리와 남부순환로를 확인했다. 신뢰할 수 있는 수치 좌표는 독립 출처에서 확인하지 못했다. 검증 도구는 서울시 10121에서 이름이 난곡사거리인 정규화 행이 한 건일 때 그 중심 좌표를 사용한다. 일치 항목이 없거나 복수이면 반경 결과를 미검증으로 표시한다. [서울연구데이터서비스](https://data.si.re.kr/node/40569) · [10121 공식 명세](https://t-data.seoul.go.kr/dataprovide/trafficdataviewopenapi.do?data_id=10121)

## 로컬 확인 방법

1. 노출 이력이 있는 이전 키를 폐기 또는 재발급하고, 새 키를 Git에서 제외된 `.env.local`의 `SEOUL_TDATA_MAP_API_KEY`와 `SEOUL_TDATA_SIGNAL_API_KEY`에 설정한다. API별 승인된 키를 사용한다.
2. `pnpm dev`로 루프백 주소에 개발 서버를 열고 `http://127.0.0.1:3000/dev/signals`에 접속한다. **데이터 조회** 버튼은 서버 작업을 한 번 시작한다. 페이지 진입만으로는 API를 부르지 않으며 운영 빌드에서 경로와 서버 작업은 차단된다.
3. MAP은 페이지당 100행을 요청하며 빈 페이지, 반복 페이지, 오류 또는 30페이지에서 중단한다. 마지막 페이지가 확인되지 않은 표본은 부분 결과로 표시한다. API가 문서에 없는 JSON 래퍼를 반환하면 스키마 오류로 중단한다. 공식 공개 샘플에서 확인하지 못한 MAP의 최상위 배열 형태는 인증 후 검증할 가정이다.
4. 각 후보 ID는 한 번 조회하며, 전송 시각으로 최신 행을 고른다. 값이 비어 있으면 미제공, 시각이 없거나 미래이면 전송 시각 미검증, 수신 검사 시점보다 10초 넘게 오래되면 지연으로 표시한다. 색상은 정상 샘플의 정지 상태에만 적용하며 시간은 원본 값으로 표시한다.
5. 프로젝트의 `.td-data-budget/`에 호출 슬롯을 원자적으로 생성해 재시작과 동시 요청을 포함해 **최대 50회**를 적용한다. 실패한 외부 요청도 예산에 포함되며 자동 재시도·폴링은 없다. 같은 개발 서버의 동시 실행은 공유하고, 완료 후 60초 이내 재요청은 직전 결과를 사용한다. 예산은 이 검증용 작업 복사본 기준이며 새로 고침이나 날짜 변경으로 초기화되지 않는다. [T-DATA 공식 호출 한도](https://t-data.seoul.go.kr/userguide/guideopenapi.do)

## 구현 검증

단위 테스트 5개, ESLint, 타입 검사, 프로덕션 빌드와 포맷 검사가 통과했다. 로컬 HTTP 검사에서 개발 화면은 200, 키 없이 조회하면 설정 안내, 프로덕션 경로는 404를 반환했다. T-DATA 외부 호출은 0회였다.

## 다음 우선순위

1. 재발급 키로 두 엔드포인트의 HTTPS 인증, 응답 형식과 MAP 페이지 종료 방식을 확인한다.
2. 10121에서 얻은 중심 좌표를 공공 지도와 대조하고, 500m 이내 목록과 ID를 기록한다.
3. 후보 ID의 10381 응답을 소량 조회해 실제 상태 종류, 잔여 원본값, 전송·수신 간 시차를 기록한다. 단위와 적색 현시 잔여값의 의미를 제공기관 및 현장 전환 관측으로 확인한다.
4. 개별 횡단보도 공간정보를 신호 방향 그룹과 대조한다. 방향 접두사를 횡단보도 위치로 바로 사용하지 않는다. [방향 규칙 자료](https://t-data.seoul.go.kr/dataprovide/download.do?id=10000)
