# 난곡사거리 보행 신호 검증

기준일 2026-11-21 (KST). 대상은 서울 관악구 미성동 난곡사거리 반경 500m다. 요청·필드 명세는 [T-DATA 조사](./seoul-traffic-api.md)를 따른다.

서울연구원 자료에서 난곡사거리와 남부순환로를 확인했다. 신뢰할 수 있는 수치 좌표는 독립 출처에서 확인하지 못했다. 검증 도구는 서울시 10121에서 이름이 난곡사거리인 정규화 행이 한 건일 때 그 중심 좌표를 사용한다. 일치 항목이 없거나 복수이면 반경 결과를 미검증으로 표시한다. [서울연구데이터서비스](https://data.si.re.kr/node/40569) · [10121 공식 명세](https://t-data.seoul.go.kr/dataprovide/trafficdataviewopenapi.do?data_id=10121)

## 로컬 확인 방법

1. 기존 개발용 키를 Git에서 제외된 `.env.local`의 `SEOUL_TDATA_MAP_API_KEY`와 `SEOUL_TDATA_SIGNAL_API_KEY`에 설정한다. API별 승인된 키를 사용한다.
2. `pnpm dev`로 루프백 주소에 개발 서버를 열고 `http://127.0.0.1:3000/dev/signals`에 접속한다. 아래의 두 수동 버튼으로 조회 단계를 제어한다. 페이지 진입만으로는 API를 부르지 않으며 운영 빌드에서 경로와 서버 작업은 차단된다.
3. MAP은 페이지당 100행을 요청하며 빈 페이지, 반복 페이지, 오류 또는 30페이지에서 중단한다. 마지막 페이지가 확인되지 않은 표본은 부분 결과로 표시한다. API가 문서에 없는 JSON 래퍼를 반환하면 스키마 오류로 중단한다. 공식 공개 샘플에서 확인하지 못한 MAP의 최상위 배열 형태는 인증 후 검증할 가정이다.
4. 각 후보 ID는 한 번 조회하며, 전송 시각으로 최신 행을 고른다. 값이 비어 있으면 미제공, 시각이 없거나 미래이면 전송 시각 미검증, 수신 검사 시점보다 10초 넘게 오래되면 지연으로 표시한다. 색상은 정상 샘플의 정지 상태에만 적용하며 시간은 원본 값으로 표시한다.
5. 프로젝트의 `.td-data-budget/`에 호출 슬롯을 원자적으로 생성해 재시작과 동시 요청을 포함해 **최대 50회**를 적용한다. 실패한 외부 요청도 예산에 포함되며 자동 재시도·폴링은 없다. 같은 서버의 중복 실행을 차단하고, 프로세스 간에는 요청 잠금을 공유한다. 예산은 이 검증용 작업 복사본 기준이며 새로 고침이나 날짜 변경으로 초기화되지 않는다. [T-DATA 공식 호출 한도](https://t-data.seoul.go.kr/userguide/guideopenapi.do)

## 429 대응 및 수동 검증

기존 개발용 키를 그대로 사용한다. 프로젝트의 `.td-data-budget/` 안에 API별 최근 결과와 마지막 429 및 재요청 가능 시각을 저장한다. 기존 슬롯 1–5를 유지했다. 상태 파일이 처음 없을 때는 이전 실측의 429와 **2026-11-21 06:38:27 KST**를 적용한다. 새 429 응답의 `Retry-After` 초 값 또는 HTTP 날짜를 반영하며, 헤더가 없거나 해석할 수 없으면 1시간 동안 보수적으로 대기한다. 제한 집계 범위가 확인되기 전까지 두 API를 함께 차단한다. 종료 시각이 지나도 요청은 자동 실행되지 않는다. [429 진단 기록](./td-data-429-analysis.md)

1. 제한 시각 이후 로컬 페이지를 새로 고침하고 **MAP 첫 페이지 1회 확인**을 누른다. 정확히 한 요청만 실행하며, 유효한 비어 있지 않은 배열만 다음 단계의 버튼을 활성화한다.
2. **반경 500m 및 보행 신호 조회**를 수동 실행한다. MAP 첫 페이지를 다시 읽고 빈 페이지, 반복 페이지, 오류 또는 30페이지에서 종료한다. 429가 오면 대기 시각을 저장하고 이 실행의 후속 요청을 중단한다. 전체 예산은 50회다.
3. 결과를 기록한다. 운영 MAP의 JSON 최상위 구조와 페이지 종료 방식, 난곡사거리 중심점 및 반경 내 교차로, 10381 실제 응답 상태와 잔여시간 의미는 미검증이다. 공식 10381 샘플과 10121 필드 예시는 단위 테스트에서만 사용한다.

프로세스 간 요청을 파일 잠금으로 직렬화한다. 서버 강제 종료 또는 호출 결과 저장 실패로 `request-lock`이 남으면 조회가 차단된다. 진행 중인 서버 요청이 없고 공급자 제한 시각을 확인한 경우에만 해당 잠금 디렉터리를 수동 정리한다. 숫자 슬롯과 상태 파일은 유지한다.

## 구현 검증

429 대응 변경 후 단위 테스트 9개, ESLint, 타입 검사, 프로덕션 빌드와 포맷 검사가 통과했다. 모의 429에서 재시도 가능 시각을 디스크에 저장하고 다시 로드해도 차단과 호출 예산을 유지하는 것을 확인했다. 로컬 개발 화면은 HTTP 200과 제한 중 비활성화된 조회 버튼을, 운영 경로는 HTTP 404를 반환했다. 이번 변경 작업의 실제 T-DATA 외부 호출은 0회이며 실제 슬롯은 5/50회 사용 상태다.

## 실제 호출 기록

사용자 요청으로 로컬에 설정된 개발용 키로 조회했다. 10121 재확인에서 HTTP 429를 받았다. T-DATA 인증 성공 여부와 호출 제한의 정확한 범위·해제 시각은 확인되지 않았다. 10121 교차로 목록과 난곡사거리 중심점이 확보되지 않아 지역 후보 ID에 대한 10381 호출은 진행하지 않았다. 첫 화면 제출의 응답 본문은 수집되지 않았으며, 두 실행을 합쳐 로컬 예산은 3/50 슬롯을 사용했다. 추가 자동 재시도는 중단했다.

## 다음 우선순위

1. 기존 개발용 키로 두 엔드포인트의 HTTPS 인증, 응답 형식과 MAP 페이지 종료 방식을 확인한다.
2. 10121에서 얻은 중심 좌표를 공공 지도와 대조하고, 500m 이내 목록과 ID를 기록한다.
3. 후보 ID의 10381 응답을 소량 조회해 실제 상태 종류, 잔여 원본값, 전송·수신 간 시차를 기록한다. 단위와 적색 현시 잔여값의 의미를 제공기관 및 현장 전환 관측으로 확인한다.
4. 개별 횡단보도 공간정보를 신호 방향 그룹과 대조한다. 방향 접두사를 횡단보도 위치로 바로 사용하지 않는다. [방향 규칙 자료](https://t-data.seoul.go.kr/dataprovide/download.do?id=10000)
